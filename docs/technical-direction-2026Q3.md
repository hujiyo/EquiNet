# EquiNet 技术方向与架构评审

## 0. 写在前面：定位与总体判断

**你们优化错了层。** 你们把绝大部分精力花在了模型结构和表示正则上——这是**好玩的部分**；而决定"任何一个数字到底有没有意义"的**评估方法论，是坏的**。这是业余团队最经典的失败模式：在测量体系不可信之前，就去雕琢被测量的东西。你们现在等于在用一把没校准的尺子，反复量一根正在被雕刻的木头，然后为刻度的抖动争论不休。

**核心论断（这一句是全文最重要的一句）：**
当前 README 与日志里的所有回测收益率，是「**幸存者偏差 + 零交易成本 + 选择偏差**」三重叠加后的**上界**，**不是期望收益**。真实期望收益完全可能在减去成本并修正偏差后落到 0 附近甚至为负。**在 P0 修复之前，请停止一切"哪个架构更好"的争论**——因为现在的评估体系根本无法分辨两种架构的好坏。

---

## 1. 优先级金字塔

| 层级 | 主题 | 杠杆 | 什么时候做 |
|---|---|---|---|
| **P0** | 可信度：选择偏差 / 阈值回看 | **决定生死** | 立即，先于一切 |
| **P0/P1** | 评估协议：point-in-time、基准、walk-forward、因果阈值、模型选择协议 | 让数字变可信 | 与 P0 同步 |
| **P1** | **真正的架构赌注：横截面（cross-sectional）** | 最大的性能天花板 | P0 验证后立刻 |
| **P1/P2** | 表示正则：VISReg λ / embedding 学习率标定（消融是唯一裁判） | 中等 | P0 之后 |
| **P2** | 模型本体（尺寸/位置编码/正则） | **不是瓶颈** | 最后，且多半不用动 |
| **P2** | 标签设计 | 中 | 随横截面一起改 |

一句话：**先修尺子（P0），再换被量的东西（P1），最后才去打磨刻度（P2）。**

## 2. P0：可信度（先修，再谈别的）

### 2.1 选择偏差 / 多重比较（selection bias）—— 把噪声当信号

**现状**（已实测）：`train.py`
- 每一轮在**验证集（仅 2025 一年，约 195 个交易日）**上跑实盘模拟，`realistic_return > best_realistic_return` 就把当前模型 `deepcopy` 存盘；
- 取 **80 轮里的历史最大值**当作"最佳模型"，并把它的收益写进文件名与 README；
- 选模型的指标 = 你最后对外报的指标，**训练集/验证集职责没有隔离**；
- 另有硬编码门槛 `stats['top_return'] >= 0.006 and stats['auc'] > 0.69` 才存 loss 模型——这些魔法数是**照着验证集手感调出来的**，本身就是过拟合。

**量化这笔偏差**：验证集日收益 std≈5%、195 天 → 单次估计的标准误 ≈ 5%/√195 ≈ **0.36%**。但你是**从 80 个高度相关的估计里取最大**，max-of-80 的乐观偏移轻松 1–2 个标准误 ≈ **0.4%–0.7%/日**。也就是说，你日志里那个"+1%~1.5%"，**还没扣成本，就可能已经虚高了接近一半**。

**修法**：
- **测试集只跑一次**，且**永远不用"你要报的那个指标"去选模型**。要么按 val loss 选、只报 test；要么用嵌套（walk-forward 内层选、外层评）。
- 把"取 80 轮最大值"改成"**预先指定决策规则**"（例如：warmup 后 val loss 最低的那一轮），不要在验证集上摸最大。
- 魔法数门槛删掉。

### 2.2 阈值回看（look-ahead）—— 隐性未来函数

**现状**（已实测，`training_utils.py:evaluate_model` 与 `run.py`）：
```
top_k = int(len(all_preds) * TOP_K / 100)
threshold = all_preds[ argsort(all_preds)[::-1][top_k-1] ]   # 用整个评估集（含未来）定阈值
```
全局阈值是**把评估期所有交易日的预测分池化后**取的分位点。实盘当天你**不可能**知道未来所有日子的分数分布，因此这个阈值编码了未来信息。

**修法**：阈值必须**因果**——用**滚动/扩展窗口的历史分位数**（例如过去 60 天的分数分布定今天的阈值），或直接改用**逐日横截面排名**（见 §4，这本来就是更对的做法）。

### 2.3 零样本日被剔除的隐性乐观

**现状**（已实测，`calculate_realistic_return`）：`avg_realistic_return = mean(daily_returns)`，而 `daily_returns` **只在当天有选股时才 append**；空仓日 `daily_stats.append((0,0.0))` 但**不进均值**。于是"模型没找到票的日子"被静默剔除，均值只在"它敢出手的日子"上计算——又一层乐观。

**修法**：空仓日应记 0 收益并计入分母（或明确声明"仅在有持仓日有效"，但要与实盘口径一致）。

## 3. P0/P1：评估协议（让数字变可信）

修完 §2 后，把评估固化成一个**没人能偷懒绕过**的统一入口（建议 `src/backtest.py`），至少强制产出：

1. **point-in-time 股票池**（含退市股，市值/状态按当日）。
2. **交易成本**（毛/净双曲线，成本可配置，含印花税+佣金+滑点）。
3. **基准对比**：沪深 300 / 中证 500 / 等权多头，报 **超额收益**，而不是绝对收益。现在全库**没有任何基准**（grep `benchmark/hs300/超额` 仅命中 matplotlib 参数）。
4. **风险指标**：年化 Sharpe、最大回撤、胜率、日收益 t 统计量、换手率、容量（4 只持仓下能装多少钱）。当前只有均值和一根 sparkline。
5. **walk-forward（扩展窗逐年重训）**：报**逐年收益的分布**，不是一个 cherry-picked 的单点数字。看到收益在哪几年为负，比看到"平均 +1%"重要一百倍。
6. **统计显著性**：日收益 t 统计量、Newey-West 调整（3 天持有 ⇒ 收益重叠 ⇒ 自相关，必须调）。
7. **模型选择协议**：内层选、外层评；测试集一次性。

> 记忆里已经跑出的信号是真实存在的：Prec@1% 0.23 vs 基线 0.069（3.3 倍），验证 AUC ~0.71。**这说明"预测能力"确实有**。我要修的是"预测能力"到"可赚的钱"之间那段被三重偏差污染的换算，不是否定信号本身。这个区别很重要。

## 4. P1：真正的架构赌注 —— 横截面（cross-sectional）

**这是我作为架构评审给出的最大一条性能天花板建议，比换任何模型结构都重要。**

**现状**：模型对**每只股票独立打分**——一个 45 天窗口进，一个概率出。它在 45 天里只看这一只票自己的 18 个特征（OHLCV + VWAP + 均线 + MACD + 布林 + K 线形态占比）。**输入里没有任何市场/板块/同行信息**（`ModelConfig.INPUT_DIM=18` 全是本股序列特征）。

**问题**：但你的任务本质是 **每天在全市场里横截面排序、选前 N**。这是一个 **ranking / cross-sectional** 问题，而你用了一个 **pointwise / 独立打分** 的模型去解。这两者之间有一道鸿沟：
- 模型无法知道"今天市场是 risk-on 还是 risk-off"，无法知道"这只票相对同行是强是弱"；
- 它对每天的绝对分数没概念，只能靠事后用一个（还带未来信息的）全局阈值去切

**旁证**：`config` 里的 **极端行情过滤**（剔除普涨/普跌日）本质上就是**给"缺市场上下文"打的一个补丁**——因为模型看不到市场，只好把市场层面的噪声日整段扔掉。**正确做法不是扔数据，是把市场上下文作为输入喂给模型。**

**修法（按成本递增）**：
1. **加横截面/市场上下文特征**（最便宜、最该先做）：每只票每天的输入里附加——
   - 当日市场宽度（涨跌家数比、你们已经算好了 `market_index.py`）；
   - 板块/行业相对强度、个股相对行业的 RS；
   - 本票分数在当日全市场的分位（推理时可用昨日分布近似）。
   - 这样极端行情过滤就可以退役（或降级为样本权重），而不是丢数据。
2. **横截面归一化层**：在 embedding 之后、打分之前，对**当日全市场同批样本**做标准化（z-score / softmax 温度），让输出天然是"当日相对排名"，而不是孤立概率。这从结构上解决阈值回看问题。
3. **（进阶）set-based / 交叉注意力头**：让当日候选股之间互相看到（Set Transformer / cross-sectional attention）。这是量化里真正的主流做法，但依赖 1–2 先跑通。

**注意**：横截面改造会让"每股独立的逐日 embedding"的价值进一步下降（见 §5），因为信息瓶颈从"单票单日"转移到"全市场相对关系"。

## 5. 表示正则（单阶段）

主训练是单阶段端到端：FFN-Embedding 与 Transformer 主干联合训练，Embedding 使用独立参数组和更低学习率；VISReg 由每个 step 独立采样的单日 batch 提供，作为表征分布的几何正则。

- 逐日编码器只负责“某一天长什么样”的统计量；跨日动量、量能形态、相对强度由主干在 45 天序列上组合——这是 `g∘f` 的分工，不是让 `f` 去预测。
- 联合训练让 `f` 在任务梯度下学习“对主干好读”的表征，不需要单独的预训练阶段。
- VISReg 保持 embedding 的边际几何（std≈`TARGET_STD`），λ 与 embedding 学习率仍需消融标定。
- 需要标定的是 `VISREG_MAIN_WEIGHT`、`EMBED_LR_RATIO`、`VISREG_AUX_BATCH_SIZE`；验证口径仍是验证集逐日 IC/ICIR。

## 6. P2：模型本体（不是瓶颈，别动）

等 P0/P1 都验证过之后再看这里，而且我预计**基本不用动**：

- **尺寸合适**：d_model=128 / 4 层 / 4 头，对这个数据量（~2000 股 × ~10 年）是合理规模，**不是瓶颈**。note 里纠结"头数 4→6→8"，这是**在刻度上雕花**，先放一放。
- **Post-Norm + 零 dropout**：对高噪声金融任务，零 dropout 是站得住的选择；但配合"80 轮 + 取最大值"（§2.1）会让验证集过拟合加剧——**真正要修的是选模型的方式，不是 dropout**。
- **位置编码**：learned 对 45 长度没问题；若以后拉长上下文，RoPE 是温和升级。
- **per-head Q/K RMSNorm、SwiGLU、输出头先验 bias**：都对，保持。

**结论**：模型这一层的工程质量已经高于你们的评估与数据层。请把力气从这里挪走。

## 7. 标签设计（P2，随横截面一起改）

`generate_label` 的五条件"强势信号"规则是手搓启发式，把你们对"什么算强"的先验**硬编码**进了标签。风险：
- 规则边界脆弱（阈值 0.05 / 0.06 / 0.08 一带的样本会被任意翻转）；
- 它是"是否触发某个模式"的分类，而你们真正想要的是**未来收益的排序**。

更干净的做法（任选）：
- **连续前瞻收益回归** + 排序目标（pairwise / listwise），让模型直接学"谁更强"，而不是"谁触发了规则 5"；
- 或 **分位数标签**（未来 3 日收益在当日横截面的分位），天然对接 §4 的横截面框架。

（你们已有 `PairwiseWeightedBCE` 的基础设施，说明排序这条路你们已经铺了一半。）

另外：`POSITIVE_RATIO=0.25` 上采样 **与** `POS_WEIGHT=4.0` **在重复纠偏**，后果是**输出概率失校准**——而选股阈值恰恰依赖这个概率。二选一即可（记忆里也已标出）。概率失校准还和 §2 的阈值回看叠加。
